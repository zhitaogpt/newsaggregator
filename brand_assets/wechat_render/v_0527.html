No. 03The AI bubble isn't like the internet bubble

🔥 HN 头条 | Cory Doctorow / Pluralistic

Cory Doctorow 在 5/26 长文中提出与多数"AI 是 1999 互联网"类比相反的论断：互联网泡沫破裂后留下了真实可用的光纤、协议、域名生态系统，下一波公司可以"白嫖"这些基建；而 AI 泡沫如果破裂，留下的资产是数据中心、GPU 和高度依赖能源补贴的产能——这些资产折旧极快、强地理绑定、需持续电力 Capex，下一代公司无法以"白菜价"接盘。与本期 #1、#2 形成三角交叉：当 Altman 撤回失业论、Uber 抱怨 ROI、市场正在重新定价应用层（#1），但同时疯狂扎进硬件链（#2），Doctorow 的警告是最大空头观点——一旦应用端 ROI 验证失败的时间窗口拉长到 18 个月以上，硬件库存会以"无可回收价值"的形态留在资产负债表上。这是 2026 下半年 AI 板块最值得反复推演的反方剧本。

No. 04Language Models Need Sleep (arXiv 2605.26099)

🔥 HN 头条 | Sangyun Lee / Sean McLeish / Tom Goldstein / Giulia Fanti（CMU）| 2026-05-25 提交

论文提出一种类睡眠的"巩固机制"：让 Transformer LLM 在长程任务推理中阶段性进入"离线巩固"状态，把激活态信息压缩固化进权重，从而绕开注意力机制对上下文长度的二次方扩展瓶颈。对开发者的现实意义：当前所有"长上下文"方案（Mamba、SSM、滑动窗口、Ring Attention）都在改注意力机制本身，而本文的思路是承认 Transformer 不变，但模仿生物大脑的"清醒-睡眠"循环——清醒时干活、睡眠时把工作记忆固化到长期记忆。如果该机制能工程化（论文有 PoC），意味着Agent 长程任务（多日协作、多轮记忆）将不再依赖外挂记忆数据库，而是模型内置一个可写权重的"睡眠回路"。结合本期 #6 Timeglass.ai 在做的"外挂 memory 层"，技术路线分歧已经显现：外挂 memory（Timeglass）vs 内置 sleep（CMU）——这将是 2026 下半年 Agent 基础设施的第一条技术分水岭。

↗ 原文https://arxiv.org/abs/2605.26099

No. 05DeepSWE：第一个无污染、长程的代码 Agent benchmark

🔥 HN 当日 | Datacurve.ai

DeepSWE 公开宣称四项突破：(1) 无数据污染（任务全新撰写，未被任何模型预训练见过）；(2) 91 个仓库 / 5 种语言 高多样性；(3) 任务 prompt 仅为 SWE-bench Pro 一半长度，但解题需 5.5× 代码量、~2× 输出 token；(4) 验证器手写、测软件行为而非实现细节。结合昨日 #7 Codex 反超 Claude Code、#3 Uber CTO 打爆 Claude Code 预算——SWE-bench / SWE-bench Pro 的分数已被怀疑被预训练数据污染，导致大模型在公开 benchmark 上越战越神，但在企业真实代码库的 ROI 持续下滑。DeepSWE 是第一个以"防污染"为设计起点的 Agent 编码 benchmark，如果 OpenAI、Anthropic、Google 在该榜单上的分数显著低于 SWE-bench Pro，将成为今年下半年评估"代码 Agent 是否真在进步"的关键标尺。

No. 06Show HN: Timeglass.ai — MCPs aren't enough, give Codex/Claude accurate memory of everything

🔥 HN Show 当日 | 项目主页

创始人在 Show HN 直接定调："MCP 不够用"——MCP 提供的是"按需调用工具"，但 Codex / Claude / Cursor 在长程项目中真正缺的是对"我之前做了什么"的可信记忆：跨 session、跨仓库、跨工具调用全链路。Timeglass 的卖点是把 IDE 操作、shell 命令、git 历史、tool call 全程喂给一个独立 memory layer，供下次 prompt 时按需检索。与本期 #4 CMU "Language Models Need Sleep" 直接对仗：(a) 学界路线 = 改模型权重让其内置睡眠回路；(b) 工程路线 = 在模型外挂一个权威 memory 服务。对开发者最实用的判断：MCP 标准目前覆盖工具调用、prompt 资源、数据 source，但"长期事实记忆"是 MCP 协议没有 first-class support 的洞——Timeglass 在做的就是这个洞，如果做大就是事实上的"Agent 记忆 SaaS 标准"。

No. 11The Open/Closed Problem in AI

Source: mempko blog（HN 头条）| Time: 2026-05-26

作者参加完第九届 MLSys 大会后写下的反思：当下 AI 系统研究的绝大多数精力都在追求"如何更高效地训练/部署 LLM"——这是一个"封闭式效率优化"问题。但他用 3D 计算机图形学发展史做类比：上世纪 90 年代图形学也曾陷入"如何更快渲染"的封闭最优化，直到可编程 shader（开放式扩展）出现才彻底改变行业。当下 LLM 的"开放式问题"（让用户/开发者向模型注入新的推理能力，而非 prompt 工程）远未被认真解决。与本期 #4（Language Models Need Sleep）+ #6（Timeglass 外挂记忆）+ #8（skills-for-humanity）形成完美回响——所有这些项目都在做"开放式"那一端：让模型学会新的思考机制 / 新的记忆机制 / 新的推理脚本。这篇博客提供了理论框架，让上述实践拼成一张完整的图：2026 下半年 AI 系统创新的真正主战场，不在 token/秒，而在"用户能给 LLM 注入什么新能力"。
