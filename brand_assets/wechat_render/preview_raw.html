## AI 技术前沿

#### 4. [Lens：3.8B 文生图模型，仅用 Z-Image 19.3% 的训练算力达到 SOTA](https://huggingface.co/papers/2605.21573)
- 🔥 HF Papers #1 of the day | 微软研究院
- Lens 用 3.8B 参数对标 6B+ 模型，**训练算力只需 Z-Image 的 19.3%**。两个杠杆：（a）单批次信息密度——基于 GPT-4.1 生成的 800M 密集 caption（平均 109 词/图）+ 多分辨率混合批；（b）架构层面的语义 VAE + 强语言编码器加速收敛。1024² 图像在单卡 H100 上推理 3.15 秒，蒸馏 turbo 版 4 步 0.84 秒。**与本报第 2 条 HBM 涨价直接相关**：当组件成本压顶，"用更少算力做到 SOTA"已成为新的核心竞争力——训练效率论文将主导 2026 下半年顶会。

#### 5. [LLM as Noisy Channels：用 Shannon 信道理论统一 Scaling Laws](https://huggingface.co/papers/2605.23901)
- 🔥 HF Papers Trending | arxiv 2605.23901
- 现有 LLM scaling laws 都是单调 power law，无法解释"灾难性过训练"（catastrophic overtraining）和量化退化等**非单调现象**。作者基于 Shannon-Hartley 定理提出 **Shannon Scaling Law**：模型参数 → 信道带宽，训练 token → 信号功率，揭示 LLM 存在"Shannon 容量"上限——超出 SNR 临界点，继续堆算力反而放大噪声。理论价值：把"为什么大模型有时反而变差"从工程经验上升为可预测的信息论必然，对预训练 budget 决策有直接指导意义。

#### 6. [Constraint Decay：LLM Agent 在后端代码生成中的"约束衰退"现象](https://arxiv.org/abs/2605.06445)
- 🔥 178 points | [Discussion](https://news.ycombinator.com/item?id=48259200)
- Sapienza 团队用 80 个绿地任务 + 20 个特征实现任务，跨 8 个 web 框架做了系统评测：当**结构性约束**（架构模式、数据库、ORM 等非功能性要求）累加时，**LLM Agent 性能平均下跌 30 分**。这一"约束衰退"现象证明：目前的 Agent 在"宽松规约"下表现优异，但一旦需要严格遵守生产级架构就会脆性瓦解。与本报第 14 条"Claude 不是你的架构师"互证——**LLM 可写代码，但难承接架构纪律**。这对企业级 AI 编码工具的能力边界给出了量化基准。

## 开发者工具与开源生态

#### 12. [用 Jujutsu 干掉 Git Rigour Fatigue](https://ikesau.co/blog/defeating-git-rigour-fatigue-with-jujutsu/)
- 🔥 97 points | [Discussion](https://news.ycombinator.com/item?id=48258437)
- 作者用 Jujutsu（jj）的工作流解决"开发大特性时无法保持每个 commit 干净"的痛点：先随性提交，最后用 `jj new -B` 创建理想 commit 序列，然后 `jj squash -i` 把混乱的"everything commit"分拆到各自语义桶中。比 `jj absorb` 和 `jj split` 都更稳。**为什么值得开发者关注**：随着 Claude Code / Codex / Reasonix 把"每个 commit 一个语义单元"的需求拉到极致，Jujutsu 的"宽容首遍 + 严格末遍"心智模型正成为 AI-native 时代的版本控制新范式。Git 之外的下一个标准接口候选。

#### 13. [本地 LLM 在"先提问再回答"的指令下表现质变](https://www.xda-developers.com/local-llm-clarifying-questions-system-prompt/)
- 🔥 29 points | XDA Developers
- 实测发现：在本地 Llama/Qwen 模型的系统提示中加入"任何非平凡任务前先问澄清问题"指令，效果**比硬调 prompt 更好**——原本需要 3-4 轮才能纠正的歧义被压缩到 1-2 轮。云端模型靠海量训练数据"读懂言外之意"，本地小模型则需要把"澄清能力"显式写出来。这与本报第 6 条 Constraint Decay 论文呼应：**LLM 在"宽松规约"下表现好但容易出错**，把"提问"作为强制前置步骤是低成本的工程缓解方案。
