🔥 HF Papers #1 of the day | 微软研究院

LLM as Noisy Channels：用 Shannon 信道理论统一 Scaling Laws

🔥 HF Papers Trending | arxiv 2605.23901

现有 LLM scaling laws 都是单调 power law，无法解释"灾难性过训练"（catastrophic overtraining）和量化退化等非单调现象。作者基于 Shannon-Hartley 定理提出 Shannon Scaling Law：模型参数 → 信道带宽，训练 token → 信号功率，揭示 LLM 存在"Shannon 容量"上限——超出 SNR 临界点，继续堆算力反而放大噪声。理论价值：把"为什么大模型有时反而变差"从工程经验上升为可预测的信息论必然，对预训练 budget 决策有直接指导意义。

Constraint Decay：LLM Agent 在后端代码生成中的"约束衰退"现象

🔥 178 points | Discussion

Sapienza 团队用 80 个绿地任务 + 20 个特征实现任务，跨 8 个 web 框架做了系统评测：当结构性约束（架构模式、数据库、ORM 等非功能性要求）累加时，LLM Agent 性能平均下跌 30 分。这一"约束衰退"现象证明：目前的 Agent 在"宽松规约"下表现优异，但一旦需要严格遵守生产级架构就会脆性瓦解。与下文 #14"Claude 不是你的架构师"互证——LLM 可写代码，但难承接架构纪律。这对企业级 AI 编码工具的能力边界给出了量化基准。

用 Jujutsu 干掉 Git Rigour Fatigue

🔥 97 points | Discussion

作者用 Jujutsu（jj）的工作流解决"开发大特性时无法保持每个 commit 干净"的痛点：先随性提交，最后用 jj new -B 创建理想 commit 序列，然后 jj squash -i 把混乱的"everything commit"分拆到各自语义桶中。比 jj absorb 和 jj split 都更稳。为什么值得开发者关注：随着 Claude Code / Codex / Reasonix 把"每个 commit 一个语义单元"的需求拉到极致，Jujutsu 的"宽容首遍 + 严格末遍"心智模型正成为 AI-native 时代的版本控制新范式。Git 之外的下一个标准接口候选。
